# tests/results/

Scratch output for codegen tests that need to write real files to disk —
assembled `.s` text, linked `.dll`/`.so` artifacts, and assembler/linker logs
produced by `codegen/tools/ExecUtils.*` (used by
`codegen/tools/test_scalar_pipeline.cpp` and
`codegen/tools/test_real_execution.cpp`) and by `CodegenDriver::lower_module_to_asm`
when run manually with `--emit=asm -o`.

Nothing in this directory is meaningful on its own — every file here is
regenerated by re-running the test that produced it. Contents are gitignored
(only this README is tracked); previously this kind of output ended up
scattered as loose `.s` files in the repository root (from tests that have
since been replaced — see `codegen/README.md`'s testing section) or wherever
a test happened to be invoked from. Point a test's scratch-file prefix here
(e.g. `assemble_and_load(asm_text, "tests/results/<name>")`) instead of the
repo root or an ad hoc temp directory so build artifacts stay in one
predictable, already-ignored place.

When running tests directly (not through `ctest`/`gtest_discover_tests`,
which already set `WORKING_DIRECTORY` to the build tree), `cd` into this
directory first, or pass an explicit `tests/results/...` prefix, so output
doesn't land in the repo root.
